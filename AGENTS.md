# web — Agent Instructions

Progressive Web App (PWA) for Rocket Lease. Vite + React + TypeScript, Tailwind for styling, shadcn/ui for base components, Supabase JS SDK for auth, `@<org>/contracts` for typed API access. Capacitor wrap planned as exit path to App Store / Play Store if needed.

## Cross-repo docs (in api/docs/)

- Domain glossary: `../api/docs/CONTEXT.md`. Spanish terms in user-facing strings, English code identifiers.
- Cross-repo conventions (RFC 7807 errors, money, dates, commits): `../api/docs/CONVENTIONS.md`.
- ADRs: `../api/docs/adr/`.

## Layout

```
src/
  routes/                    # TanStack Router (or React Router v7) route tree
    (auth)/                  # auth screens (login, signup, forgot)
    (conductor)/             # conductor-only screens
    (rentador)/              # rentador-only screens
    __root.tsx
  features/<feature>/
    hooks/                   # business logic hooks (useReservation, etc.)
    components/              # feature-specific composite components
    api/                     # thin wrappers over apiClient (one per resource)
    types.ts                 # local types (re-export from @<org>/contracts when shared)
  ui/                        # presentational components (shadcn/ui copies, edited)
  i18n/
    es.ts                    # all user-facing strings (centralized for later i18n)
  lib/
    supabase.ts              # Supabase client (browser SDK + localStorage persistence)
    api-client.ts            # createApiClient(...) from @<org>/contracts
    storage.ts               # localStorage / IndexedDB wrappers
    formatters.ts            # money, date, distance helpers
    queryClient.ts           # tanstack-query setup
  pwa/
    register-sw.ts           # service worker registration via vite-plugin-pwa
  styles/
    globals.css              # Tailwind base + theme tokens
public/
  icons/                     # PWA icons (192, 512, maskable)
  manifest.webmanifest       # generated by vite-plugin-pwa
```

## Layer rules (this repo)

1. `ui/` components are **presentational only**. No API calls, no business logic, no `useEffect` for side effects beyond animations. Receive data + callbacks via props.
2. `features/*/components` may compose `ui/` and call hooks from `features/*/hooks`. They never call the API directly.
3. `features/*/hooks` orchestrate API calls (via `features/*/api`) + state (tanstack-query). They expose stable, typed return shapes.
4. Route components in `routes/` compose feature components and read route params. Routes are thin.
5. **All API calls go through `apiClient`** from `@<org>/contracts`. No direct `fetch` calls in app code.
6. **All user-facing strings** in `src/i18n/es.ts`. No string literals in components. Lint catches.
7. **Money** displayed via `formatters.formatMoney(cents, currency)` (returns `Intl.NumberFormat`-formatted ARS by default). Never display raw numbers.
8. **Dates** displayed via `formatters.formatDate(iso, format)`. UTC → `America/Argentina/Buenos_Aires` conversion happens here, nowhere else.

## Brand & Design System

All visual decisions — colors, typography, spacing, iconography, tone of voice, component behavior — are governed by `BRAND.md` at the root of this repo. Read it before implementing any UI work.

Key rules derived from it:
- **Color tokens** live in `src/styles/globals.css` (`@theme` block). Never use hex literals in components.
- **Primary font**: Poppins. Loaded via Google Fonts in `index.html`.
- **Icons**: Phosphor Icons (`@phosphor-icons/react`). `weight="regular"` at rest, `weight="duotone"` when active. No Lucide.
- **Role colors**: conductor → cian `#06B6D4`, rentador → ámbar `#F59E0B`. Apply in role-specific contexts.
- **Buttons**: primary always `rounded-full` (pill). Cards and inputs `rounded-xl` (12px).
- **Logo assets**: `public/logo-symbol.png` (transparent, for use inside the app), `public/logo.png` (dark bg, for PWA/OG).

## Styling

- Tailwind classes only. Example: `<div className="flex-1 bg-surface-1 p-4">`.
- No inline `style={{ ... }}` except for animated values or dynamic gradient fills (e.g. role-aware gradients).
- Tokens defined in `@theme` block in `globals.css` (Tailwind v4). No hex literals in components.
- Dark mode is the default. Light mode applies only to specific functional flows (long forms, search).
- Mobile-first: design at 375px width first, scale up. Use `sm:` / `md:` for larger.

## State + data fetching

- **tanstack-query** (`@tanstack/react-query`) for all server state. Never `useState` for server data.
- Query keys follow the convention `[feature, resource, ...params]`, e.g. `['vehicles', 'list', filters]`.
- Optimistic updates: only on actions that the user initiated and where the server has a clear contract (e.g. toggling favorite). Otherwise wait for server confirm.
- Auth state: Supabase session via `useSession()` hook (custom wrapper around `supabase.auth.onAuthStateChange`). Persist to localStorage (default Supabase behavior in browser).

## PWA specifics

- Manifest + service worker generated by `vite-plugin-pwa`. Config in `vite.config.ts`.
- **Install prompt:** show in-app prompt after user signs up (deferred via `beforeinstallprompt` event capture).
- **Offline strategy:** `NetworkFirst` for API calls, `CacheFirst` for static assets, `StaleWhileRevalidate` for images.
- **iOS quirks:** PWA install only via "Add to Home Screen" (Safari). Push notifications require iOS 16.4+ AND home-screen install. Treat as best-effort, not core flow.
- **Update flow:** new SW version → toast prompts user to refresh. Auto-skip-waiting forbidden (data loss risk).
- **Capacitor exit path:** when wrapping for app stores, `capacitor.config.ts` lives at root, `npx cap add ios|android` generates platform dirs. Web build stays source of truth.

## Error handling (consuming RFC 7807 from api)

All errors from `apiClient` arrive shaped as:

```ts
type ApiError = { code: ErrorCode; status: number; detail: string; ... }
```

Map to user-facing messages by `code`, not by HTTP status. Display via toast or inline form error. Use `i18n/es.ts` keys for messages, not the raw `detail` (during dev `detail` is fine for tooling).

## Multi-role behavior

`User` has `isConductor` and `isRentador` flags. Routes under `(conductor)` are gated by `isConductor`; `(rentador)` by `isRentador`. A user with both flags sees a role-switcher in the header. Default for new users: `isConductor=true`, `isRentador=false`. The flag flips to `true` for `isRentador` after publishing the first vehicle (transition handled by api on first vehicle create).

## Tests

- **Unit**: Vitest + React Testing Library for hooks and pure functions.
- **Integration**: RTL screen-level tests with API mocked via MSW. The `apiClient` is replaced with a mock client in tests.
- **e2e**: Playwright flows under `e2e/`. Run on Chromium in CI on `dev → main`. Mobile viewport (Pixel 5 / iPhone 13) preset.
- Snapshot tests are forbidden for UI components (rot fast, low signal). Allowed only for stable serialized outputs (formatter unit tests).

## Local dev

Prereq: clone `contracts` next to `web/` (same parent directory). web depends on `@rocket-lease/contracts` via `link:../contracts` — see `../api/docs/adr/0007-contracts-as-source.md`. A `preinstall` script aborts if the sibling is missing.

- `pnpm install`
- `make dev` — runs `vite`. Opens at `http://localhost:5173`.
- For testing against local api: set `VITE_API_URL=http://localhost:3000` in `.env.local`.
- For testing PWA install / SW: `make build && pnpm preview` (SW only registers in production build).

Editing any `.ts` under `../contracts/src/` triggers HMR here automatically — no rebuild, no install.

## CI

`.github/workflows/ci.yml` runs typecheck + lint + tests + build. It checks out `contracts` as a sibling (same branch if present, else PR base ref) before `pnpm install`. Vercel deploys via its native GitHub integration; the install hook in `vercel.json` clones contracts as a sibling.

## Pointers for AI agents

- Always import types from `@<org>/contracts`. If a needed type is missing, propose adding it to contracts (separate PR) before continuing here.
- Never invent an endpoint. Endpoints come from `@<org>/contracts/client`. If missing, contracts PR first.
- Never write a hex color or magic number in a component. Add a token to Tailwind config or a constant in `styles/`.
- When in doubt about UI behavior: check the user story acceptance criteria (Gherkin format, "DADO/CUANDO/ENTONCES") in the Trello ticket / `Backlog-US` excel sheet.
- Mobile-first always. Test at 375px first, then scale. Don't assume hover/pointer events — design for touch.
